# Δ Deltabase

本地个人产品研究工作台。采集中国／美国 App Store 非游戏分类榜单和 YC 公开增长岗位，手动记录融资公告，关联公司与产品，保存证据和创业机会假设。

项目管理：[范围与路线图](docs/PROJECT.md) · [架构决策](docs/ARCHITECTURE.md) · [当前进度与验收](docs/STATUS.md) · [协作约定](AGENTS.md)。

## 本地启动

需要 **Node.js 24 LTS**。在项目根目录执行：

```bash
nvm use                  # 已安装 nvm 时使用
npm ci
npm run build
npm start
```

打开 <http://127.0.0.1:3000>。`Ctrl+C` 停止；下次运行 `npm start` 即可，数据会保留。npm 11.19 的安装脚本许可已经按版本记录在 package.json；老版本 npm 会使用常规安装流程。

开发模式：`npm run dev`，打开 <http://127.0.0.1:5173>。前端通过 Vite 代理访问 3000 端口的 Fastify。依赖或源码有变化后，日常模式需重新 `npm run build` 并重启。

首次启动会自动建立数据库，并分批采集 156 个榜单组合：26 个非游戏顶级品类 × 中美两个市场 × 免费、付费下载、畅销三种榜。通常需要几分钟，超时重试会延长时间；页面先展示已完成的部分。目录、贴纸等旧类别可能没有条目，这会明确显示“暂无数据”。

这是一份真实数据工作台，没有自动注入演示数据。第一次采集只有基线，没有虚构历史信号。

## 使用路径

- **榜单浏览**：市场、类别、榜单筛选及本地搜索；付费下载榜单独观察。
- **研究工作台**：石墨白主题，列表与证据侧栏并排展示；点击产品即可核对前后排名、采样时间、原始快照，直接关注或保存机会笔记。进入完整档案后可返回原来的筛选与选中记录。窄屏点击产品会滚动到证据区。
- **交叉观察**：对免费下载安装的产品，以 App ID 关联免费榜和畅销榜，取并集而非交集。可筛选“畅销前 20，免费榜 50 名后或未观察到”；这是筛选条件，不是变现能力分。两侧保留各自观察时间。
- **变化信号**：同一来源／市场／类别／榜单的前后快照比较，识别新进入观察列表、上升至少 10 位；关注产品在详情更新时记录版本变化。
- **观察名单**：收藏、取消关注，或通过 App Store 链接／App ID 加入产品。所选地区必须能查询到资料。
- **产品详情**：按市场保存名称、定价和详情，查看采样曲线、原始快照，编写机会笔记、标签。
- **增长雷达**：自动采集 YC Jobs Marketing 公开岗位，按公司聚合渠道证据；手动录入 SideShift／Wellfound 线索，支持编辑、关注、忽略、研究笔记和人工确认 App 关联。
- **融资观察**：手动录入公告或待核验线索，选择已有公司或创建独立公司；同轮可追加多份来源，疑似重复由人工确认，编辑与核验保留历史。
- **数据状态**：显示各来源检查结果、错误和运行进度；可重试、关闭榜单类型或品类。设置变更对下一轮采集生效。

收藏和笔记属于产品，跨市场共享；商店资料和排名按市场分别记录。忽略只隐藏默认发现结果，不删除历史。

侧栏笔记未保存前暂存于当前浏览器标签页，切换产品或刷新仍可继续填写；关闭标签页后草稿可能丢失。点击“保存笔记”后才会写入本机 SQLite。工作台有近期信号时默认展示变化，没有信号时从榜单浏览开始。

## 更新和存储

Node 服务启动时检查超过 24 小时未检查的来源，并重试失败来源；页面可手动触发更新。没有安装系统定时任务。程序关闭、电脑休眠时不会采集，保持程序开着也不会自动每 24 小时执行一次，需手动刷新或重新启动。关闭浏览器标签不影响仍在运行的服务。

SQLite 文件：`data/deltabase.sqlite`。榜单原始 JSON 经 gzip 压缩一并保存，收藏、标签、笔记、任务状态、快照和差异事件均持久化。SQLite 使用 WAL，数据目录已被 Git 忽略。首版不自动清理历史。

```bash
npm run backup
```

使用 SQLite 在线备份接口，在 `data/backups/` 生成完整数据库副本。不要直接复制正在使用的 `.sqlite` 主文件代替在线备份。

恢复时先停止服务，将当前数据库和同名 `-wal`、`-shm` 文件整体移到其他目录保留，再把备份复制为 `data/deltabase.sqlite`，最后重新启动。不要把备份与旧 WAL 文件混用。

可选环境变量：

| 变量        | 默认值 | 作用                                 |
| ----------- | ------ | ------------------------------------ |
| `DATA_DIR`  | `data` | 数据库目录，相对项目根目录或绝对路径 |
| `PORT`      | `3000` | 本地 API 与构建后页面的端口          |
| `AUTO_SYNC` | `1`    | `0` 禁用启动采集，仍可手动刷新       |

默认只监听 `127.0.0.1`，没有登录功能；不是公开互联网部署方案。笔记和收藏不会上传到云端。网络请求用于读取 Apple 公开榜单、Lookup 资料、产品图标及 YC 公开招聘页面。SideShift／Wellfound 只保存你填写的原始链接和研究记录，不自动访问或抓取这些链接。

## 数据口径

来源：[Apple 分类目录](https://itunes.apple.com/WebObjects/MZStoreServices.woa/ws/genres?id=36)、[分类免费榜示例](https://itunes.apple.com/us/rss/topfreeapplications/limit=100/genre=6007/json)、[分类付费榜示例](https://itunes.apple.com/us/rss/toppaidapplications/limit=100/genre=6007/json)、[分类畅销榜示例](https://itunes.apple.com/us/rss/topgrossingapplications/limit=100/genre=6007/json)、[Lookup 文档](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/LookupExamples.html)。

- 榜单位置是相对信号，不是公开下载量或收入金额。旧版畅销榜标为实验性，不保证长期可用或收入统计口径。
- 下载价格不是订阅价格；畅销排名不代表广告、站外收入或利润。
- “非游戏”按 Apple 顶级类别定义；教育、娱乐类可能包含游戏化应用。
- 请求最多 100 条不意味着返回恰好 100 条。不出现只表示本次列表未观察到，不推断下架或排名第 101。
- 首次采集不产生变动事件。重复相同快照去重；来源过期、重复 ID、分类不符和格式错误不会覆盖已有快照。
- 空榜不推导退出；失败保留最近有效数据。来源更新时间、实际采集时间分别保存；页面日期按北京时间显示。
- 相邻有效采集间隔可能不是一天，信号显示对比时间。图表不插补数据，超过 36 小时的点不连接。
- Lookup 按需获取，缓存 24 小时、调用间隔至少 6 秒；不对所有榜单产品全量查询详情。

## 工程结构与验证

`src/` 为 React 工作台；`server/` 包含 Fastify API、Apple 适配器、任务执行器、SQLite 存储和 Drizzle 迁移；`shared/` 为分类及共享类型；`tests/` 为规则、API 和浏览器测试。

```bash
npm test                     # Vitest：解析、快照、信号、跨市场、API、备份恢复
npm run build                # TypeScript 检查与前后端构建
npx playwright install chromium
npm run test:e2e              # 独立测试数据库，启动 3100 端口
npm run db:generate           # schema 变更后生成待审阅的迁移
```

E2E 样本明确标为测试数据，只写入 `test-results/e2e-data/`，不会触及实际 `data/`。浏览器测试覆盖交叉观察、收藏、标签、笔记、刷新后的持久化、来源开关和移动视口。

AI 分析、融资自动采集、后台定时服务与跨设备同步保留为后续扩展。


## 信源二：增长投入雷达

入口：<http://127.0.0.1:3000/growth>，或侧栏「增长雷达」。

1. 点击「更新 YC Jobs」读取 [Marketing 公开列表](https://www.ycombinator.com/jobs/role/marketing)和岗位详情。首轮通常需要数分钟；页面显示进度，已完成的部分会逐步出现。
2. 按公司、来源、渠道检索。岗位正文中的规则匹配片段作为标签依据，可展开完整正文和保存的证据版本。
3. 打开公司，关注／忽略、记录机会假设；从本地 App 库搜索并确认关联。尚未入库的 App 可先在「观察名单」添加。
4. 点击「录入线索」，保存 SideShift／Wellfound 的 HTTPS 原始链接和自己的观察。可选择已有公司，分别填写被推广产品、发布机构、工作地点、目标市场以及报酬口径。编辑记录会保留旧版本。

### 采集与证据边界

- YC 只覆盖 Marketing 的公开样本，并非全平台或某公司的全部招聘岗位。每轮也检查最多 50 个已知但不在列表中的详情，按上次检查时间轮换。
- 请求串行，间隔至少 1.2 秒，每次超时 25 秒。遇到 401／403／429 停止本轮，不绕过登录或访问限制；页面结构、身份校验或请求失败保留已有资料。
- 初次有效列表中的岗位作为基线，即使某条详情稍后才成功，也不会误报为新招聘。以后首次发现的新 ID 标为「新发现」，不等同于刚发布、净增岗位或已实际招到人。
- 正文、薪资等内容改变才增加版本；相对发布时间自然变老不产生变化信号。即使内容未变，每次成功采集仍保存观察记录。A→B→A 会保留三次版本。
- 未出现在公开列表不代表关闭。当前没有可靠的自动关闭判定；HTTP 404 也只记为检查失败。
- 来源发布时间经常只是「2 months」等相对描述，原样保留，不伪造精确日期。时间线显示的是本地观察时间。
- 渠道标签使用本地规则，保留命中文字，可能漏判或误判。公司陈述与人工研究记录分别标记；不生成 PMF、收入或成功概率评分。
- 薪资与创作者报酬保留原文和周期，不据此估算营销预算；工作地点和产品目标市场分别记录。发布机构可能是代理商，不能自动等同于被推广产品。
- 手动链接按来源域名校验并去掉常见追踪参数，同一来源链接禁止重复录入。不同平台同名公司不自动合并，录入时可以主动选择已有公司。

### 本地实现

沿用同一个 SQLite 文件，新增 `growth_*` 表；迁移为增量创建，不改写原有 App、榜单或笔记。公司与 App 是可解除的人工关联，独立产品不依赖 Apple ID。

`server/yc.ts` 负责 YC 页面解析和证据分类，`growth-sync.ts` 负责执行／中断／失败记录，`growth-store.ts` 负责历史版本，`growth-api.ts` 提供本地 API，`src/growth.tsx` 提供公司视图和线索录入。

增长采集与榜单采集各自运行、各自显示状态。`AUTO_SYNC=0` 同时禁用两者的启动更新；默认启动时检查是否超过 24 小时，失败来源可重试。不安装定时任务，不每天导出静态网页；历史版本和每次观察保存在数据库里。

验证新增了 YC 解析／身份校验、基线和后续发现、失败保留、平台阻断停止、重复刷新、版本回退、手动来源校验、编辑历史、公司筛选、App 关联以及浏览器持久化和移动布局测试。测试数据只写入独立测试数据库。

## 信源三：融资公告手动 MVP

入口：<http://127.0.0.1:3000/funding>，或侧栏「融资观察」。

1. 录入公告，选择已有公司并填写身份依据，或创建独立公司；没有 App、招聘岗位、金额或日期的公司也能保存待核验线索。
2. 保存原文链接、发布方、摘要和支持字段。金额区分本轮、累计、估值，保留币种、约数、区间与原文；未知信息留空。发生时间、公告时间与本机首次收录时间分别记录。
3. 疑似重复时核对已有记录：同一轮追加来源；确为另一轮则说明另建理由。系统不按公司同名自动合并，也不把同一篇文章等同于唯一融资事件。
4. 在详情查看公司已有 App 关联、证据、编辑版本和人工核验记录；可编辑、归档或恢复。归档保留历史，不删除证据。访问失败只记录核验结果，不清空上次有效内容。

融资链接仅用于保存与人工打开，服务器不会自动访问、抓取或提取。保存采用事务、幂等键和版本检查：响应丢失后可重试；过期草稿会提示冲突，需核对后保存。表单草稿保存在当前浏览器标签页，刷新可恢复，关闭标签页可能丢失。

融资公司复用现有公司身份与 App 关联，但不会因单独录入融资而增加增长雷达的公司数。融资本身不证明到账、收入、PMF 或成功，不生成金额汇总和成功概率评分。

模型和接口见 [融资 API 契约](docs/design/funding-api.md)，真实样本及反例见 [研究验收包](docs/research/funding-acceptance.md)。数据仍存于本机 SQLite；测试样本不自动导入个人数据库。
