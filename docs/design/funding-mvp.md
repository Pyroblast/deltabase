# 融资信源 MVP 方案：手动核验官方公告，关联已有公司

研究日期：2026-11-01，北京时间。本文件保留立项时的研究与建议；用户已于同日批准手动 MVP。实施采用复用公司身份、修正增长统计的方案，最终接口以 [funding-api.md](funding-api.md) 为准，交付状态见 [STATUS](../STATUS.md)。自动采集与数据服务采购未获纳入本轮。

本轮只阅读项目文档、现有增长模型和公开网页；未启动采集、未访问或改写真实数据库、未修改源码、未提交 Git。网页核验使用检索/阅读工具，可能命中缓存；不能据此宣称本机采集器或服务接口已经跑通。

## 1. 建议的最小交付

先做「融资公告记录」：用户阅读公司或投资方公告，填写一条结构化事件，保留依据，选择已有公司或创建独立公司；同一轮融资可追加多条来源。它回答：**谁宣布了什么融资、信息何时公布、有哪些可核对的依据，以及与已观察的增长岗位有什么关系。**

首版只有手动录入、编辑历史、疑似重复提示、追加证据、公司关联、筛选和研究笔记。已有 App 关联继续由用户确认。不做全网抓取、数据库 API 接入、融资总额排行榜、估值推算、AI 自动抽取或“融资后一定增长”的结论。

接入范围建议为：已有 YC 研究公司优先，兼容独立公司和中文公告。首轮验收用 BoldVoice、Agave 的真实公告，以及 Educato 的信息缺失情形。语言兼容不等于已具备中国融资事件覆盖。

| 候选来源 | 本轮核验结果 | 首版取舍与限制 |
| --- | --- | --- |

| IT 桔子 | V2 文档有投资事件、公司 ID、金额/币种、投资方、关联新闻及创建/更新时间；认证需分配的 appid/appkey | 后续中国市场候选。文档可读不代表账户有业务数据权限；未取得凭证或测试正式接口。接入前需确认授权范围、计量单位和更新能力 |
| TechCrunch | 有 RSS 使用条款；未验证融资专用 feed 的当前完整性 | 首版仅作人工发现入口。RSS 展示需保留署名和原文链接；不承诺全文采集。媒体报道需另外标记证据性质 |

核验依据：[Agave 公司公告](https://useagave.com/blog/announcing-agaves-15m-series-a)、[Accel 投资公告](https://www.accel.com/news/leading-agave-s-series-a-ai-infrastructure-for-the-construction-industry)、[BoldVoice 公司新闻稿](https://www.prnewswire.com/news-releases/boldvoice-raises-21m-series-a-to-give-a-billion-non-native-english-speakers-their-own-ai-voice-coach-302671777.html)、[Crunchbase API 权限说明](https://data.crunchbase.com/docs/api-essentials)、[融资搜索文档](https://data.crunchbase.com/docs/find-recently-funded-companies)、[Dealroom API 产品说明](https://dealroom.co/products/dealroom-api/)、[公开样本索引](https://dealroom.co/llms.txt)、[IT 桔子 V2 投资事件](https://www.itjuzi.com/shujuapi/V2BaseComponents/event/v2_investevent.html)、[V2 认证](https://www.itjuzi.com/shujuapi/V2BaseComponents/oauth2.0/get_access_token.html)、[TechCrunch RSS 条款](https://techcrunch.com/rss-terms-of-use/)。这些是来源核验，未构成服务采购建议或已取得的许可。

特别注意 IT 桔子的字段语义：文档中的 `detail_amount` 单位是“万”，`juzi_detail_amount` 是等值人民币估算；新闻披露时间、投资时间、数据库创建时间和更新时间也各不相同。未来适配器必须显式转换和标注，不能直接把数字当原币金额或把更新时间当发生时间。

## 3. 真实公告样本与研究试点对齐

已阅读 [三案例研究试点](../research/2026-11-01-pilot.md)。其中身份核验与当前库内 ID 可用于后续选择，但本轮没有确认任何新关联或把样本录入数据库。

### 3.1 BoldVoice：已有增长公司与 App 身份依据

- 研究报告定位：公司 `yc:24065`，App 身份候选 `1567841142`；是否落库仍由用户确认。
- [公司新闻稿](https://www.prnewswire.com/news-releases/boldvoice-raises-21m-series-a-to-give-a-billion-non-native-english-speakers-their-own-ai-voice-coach-302671777.html)提供：2026-01-28 公告、Series A、`$21 million`、Matrix 领投，并列出其他参投机构。发布者是 BoldVoice。
- 足以建立“公司宣布融资”的记录。具体交割日、到账时间、估值未由该公告核定，保持未知。金额保留 `$21 million`；币种标准化须记录人工判断依据，不把所有 `$` 一律当 USD。
- 录入时本地发现日期为实际录入时刻；不能把这条一月公告在十一月录入后展示成“今天完成融资”。招聘岗位出现与融资公告先后只能并列观察，不推出因果。

### 3.2 Agave：同轮多证据、金额口径和品牌域名变化

- 公司[公告正文](https://useagave.com/blog/announcing-agaves-15m-series-a)称本轮为 `$15M` Series A、Accel 领投、YC 继续参与，另述累计融资超过 `$20M`。**本轮和累计金额必须分开，不能相加。**
- 公司[文章列表](https://useagave.com/blog)标注日期 2026-07-07；[Accel 的投资文章](https://www.accel.com/news/leading-agave-s-series-a-ai-infrastructure-for-the-construction-industry)也标注 2026-07-07，并支持 Series A 领投关系，但本次读到的投资文章没有给出本轮金额。字段证据需精确对应：不能让“金额”的依据指向未披露金额的页面。
- 投资方文章直接链接 `useagave.com`，公司公告的招聘入口又指向 YC。旧域名/同名公司只作候选，关联到库内 Agave 前仍需核对官网链路，不按字符串强行合并。
- 用两篇公告合成一个事件、两份证据；它们是交易相关方陈述，不因来源有两个就称为独立审计。首版可以完全不关联 App，验证独立 B2B 公司路径。
- 公司公告详情页混有模板指标和客户案例模块；这些不是融资字段，说明不能只凭金额关键词在整页抓取结果里选数字。

### 3.3 Educato：证据不足时保留线索，而非补造融资

研究报告定位公司 `yc:29605`，App 身份未确认。[官方 Press & Media](https://www.educato.com/press)介绍 YC 背景，但本次读取未提供可完整核定的融资轮次、金额和交割日期。

可保存“待核验的公司背景线索”，不因此生成已确认轮次。不能把 YC 的一般投资安排套用到单家公司，也不能把查不到公告写成“没有融资”。未在本轮确认的金额保持 null。

### 3.4 Reframe：延续试点的身份和时效边界

研究报告定位公司 `yc:23832`，外部 App 身份已核对但当时未在本地库收录。该结论只涉及产品身份。本轮没有核定 Reframe 的完整融资公告，不将其列为已确认融资样本；后续若补充证据，继续沿用报告中的身份核验路径。不得为了三个案例都出现融资而填入无依据的事件。

## 4. 可获取字段与数据口径

不要求每个字段都有值。允许完整公告、部分披露以及只有背景线索三种情况；必填项仅为本地记录标题、公司（已有或新建）、至少一个合法来源 URL、证据性质、自己的摘要/短摘录。

| 字段组 | 首版建议字段 | 规则 |
| --- | --- | --- |
| 身份 | 本地 `company_id`、公告中的公司名、官网/法律主体原文、人工关联依据 | 发布机构、融资主体、被推广产品分别看待；无 App 可保存 |
| 事件 | 本地 UUID、`record_kind`（融资事件/待核验线索）、`round_raw`、可选 `round_normalized` | 原始“A+ / extension / strategic”等说法不丢失；不强制映射成标准轮次 |
| 金额 | `amount_raw`、`amount_scope`（本轮/累计/估值/混合未拆分）、`amount_kind`（精确/约数/范围/下界/未披露）、可空币种与规范化数值 | `数千万` 不变成一个精确数；`over` 保留下界语义；未披露不等于 0；货币值用十进制字符串或整数最小单位，不用浮点数比较 |
| 交易边界 | `financing_type`（股权/可转债或 SAFE/债务/混合/未说明）、`status_raw` | 首版主路径是公司融资公告。募资意向、已签约、已完成不能混同；并购、基金募资不纳入本轮统计 |
| 投资方 | 名称原文、角色（领投/参投/未说明）、对应证据 ID | 机构列表不完整时明示；不自动建立全局投资人知识库 |
| 资金用途 | 自己概括的用途、支持证据 ID | 这是公司计划，不是实际支出；不从招聘薪资推预算 |
| 证据 | URL、发布者、来源角色、标题、发布/更新时间原文、短摘录/研究摘要、核验时间、关联字段 | 新闻稿平台域名不决定发布者；每个关键字段可追溯到支持它的证据 |
| 核验 | 未核验/已核对原文/有冲突、未解问题、核验人（本地自己）、时间 | “已核对原文”只表示核对来源陈述，不表示独立确认资金到账 |
| 研究 | 公司共享笔记、事件级疑问/下一步 | 保持来源事实、公司陈述和个人判断分开 |

金额混合（例如“股权加债务合计 X”）若无法拆分，保留原文且不进入纯股权合计。首版不做货币换算、融资总额汇总或估值排名，避免累计、分期到账和追加轮重复计数。

## 5. 三种时间必须独立

| 时间 | 含义和存储 | 展示/未知处理 |
| --- | --- | --- |
| `occurred_*` | 来源明确说的事件发生/交割时间；保存原文、精度（年/月/日/时刻/未知）及对应证据 | 没披露就 null。不得拿公告日或数据库日期补齐；只说月份不填该月 1 日 |
| `published_*` | 每份证据的发布时间及原始时区；事件的“公告日”是有依据的、已选择的公告日期 | 多篇来源各有日期。转载时间不覆盖原始公告；日期冲突可并存并等待判断 |
| `first_seen_at` / `observed_at` | 本地首次保存和每次核验时间，精确 UTC；界面按北京时间展示 | 永不回填为历史公告日。今日录入旧公告显示“今天新收录 · 公告于某日” |

另存 `source_updated_*` 与本地 `updated_at`：前者是网页标注更新时间，后者是编辑记录时间，都不当作融资发生时间。只有带明确时区的来源时刻才转换 UTC；只有日期则按原日期保存，不伪造时区。

排序默认按本地新收录；提供“公告日期”筛选并明确日期类型。日期未知进入独立分组，不能排成今天。历史基线导入与日常新收录分开标记；两者均不自动声明事件是新发生的。

## 6. 公司模型兼容方案

现有 `growth_companies` 已保存公司 UUID/YC 标识、官网、笔记、关注状态，`growth_app_links` 保存人工 App 关联。按照 ADR-002，**建议第一版复用这个身份，不立刻进行全项目表重命名或强行统一外部 ID。**

建议融资事件的 `company_id` 外键指向现有 `growth_companies.id`；新增纯融资公司使用来源无关 UUID 前缀，例如 `company:<uuid>`。现有 `yc:*` 和 `manual:*` ID 保持不变。访问层为融资提供窄的公司查询/创建方法，避免为建立公司而伪造一条增长岗位。

兼容性注意：当前增长列表的总公司数来自全部 `growth_companies`。一旦创建纯融资公司，增长页面的“公司数量”会被扩大。实施时必须将**增长列表/增长统计限定为有增长线索的公司**；通用关联选择器可以查全部公司。新增测试验证纯融资公司不造成增长空卡片或虚增增长覆盖。

用户可选择已有公司，系统可依据官网域名/已保存别名提出候选，但不能按同名、相似图标、品牌名或域名重定向自动确认。共享产品域名、代理商域名和公司更名都可能误匹配。关联依据作为融资记录版本的一部分保存，改关联必须有历史；不自动迁移 App 关联或覆盖公司笔记。

融资详情可链接现有公司研究页，并汇总该公司的增长线索与已确认 App 链接；若公司无岗位，则融资详情自身承担阅读/笔记入口，不能把“增长证据 0 条”当作错误。长期是否将公司页改为来源无关路由留待总控决定，首版不以此重构为前置条件。

## 7. 最小存储与接口草案

沿用 Fastify、SQLite、Drizzle 的增量迁移，不引入云服务、任务队列或新账号。以下为建议模型，尚未创建表。

| 对象 | 最小职责 |
| --- | --- |
| `funding_events` | 稳定事件 ID、公司 FK、当前结构化字段/研究状态、当前版本号、首次发现时间、归档状态 |
| `funding_evidence` | 一份公开文档的原始 URL、保守规范化 URL、发布者、来源角色及首次收录时间；不把 URL 当融资事件 ID |
| `funding_event_evidence` | 事件与文档多对多关联，保存支持字段/位置/摘要。一篇文章可能回顾多轮，一轮也可能有多篇公告 |
| `funding_revisions` | 每次有意义编辑后的不可变版本，包含事件字段、证据解释/关联关系、关联公司及修改原因；记录 A→B→A |
| `funding_observations` | 每次人工核验的时间、文档 ID、结果、当时的证据内容摘要/指纹、错误信息；无变化也可登记，不制造新事件 |

不为手动模式伪造自动抓取 run 或“每天更新成功”。证据内容只保存必要摘录和自己的摘要；不默认存整站 HTML、整篇媒体全文或受许可限制的数据导出。变更版本通过固定顺序的规范化对象计算指纹，排除核验时间、展示格式等易变字段；投资方顺序不变成内容差异，但角色变化算变更。

建议接口：融资事件列表/详情、创建、基于版本号更新、追加/解除证据关联、人工核验记录。写入事件和首条证据须处于同一事务；重复提交带幂等键，编辑带预期版本，冲突返回明确提示。原始链接只验证 HTTP(S)、拒绝凭据和脚本协议；**首版服务器不访问用户输入的 URL**，无需引入通用远程抓取器。

## 8. 事件去重与冲突处理

把三个问题分开：一次请求重试、同一文档重复导入、不同文档谈同一事件。

1. **请求幂等**：相同幂等键返回原事件，不新增版本或观察次数；用户明确“再次核验”才增加观察记录。
2. **文档去重**：去除 fragment 和明确的 `utm_*` 等追踪参数，保留原 URL。不能通用删除业务查询参数、强行改写大小写路径或把所有尾斜杠等价化。规范化 URL 相同则复用文档，但允许它支持多轮事件。
3. **业务事件候选**：同一已确认公司、轮次/追加关系、公告日期邻近（建议 90 天，可调整）、金额/币种与投资方相符时提示可能同轮。金额缺失仍可提示；冲突只降低匹配确定性，不制造两轮“事实”。这些条件用于提示，**不设置为数据库唯一键**。
4. **人工归并**：用户在保存前选择“追加到已有轮次”或“确认为另一轮”，并记录原因。已有重复事件可先归档副本并保留原 ID/去向，不能硬删除证据或悄悄改变计数。
5. **特殊关系**：extension、A+、追加融资、分期交割可能是原轮延伸，也可能被来源作为新事件；保留 `related_event_id` 和关系原文，由人判断。不只凭同轮名称合并，更不能把累计融资写成另一笔本轮融资。
6. **字段冲突**：不同来源的金额/日期/投资者说法均保留在各自证据里；当前事件字段选择哪份依据需要可追溯。无解时标“有冲突”，不按较新网页、较大金额或付费数据库自动覆盖。

真实验收示例：Agave 官网与 Accel 公告应能成为一个事件的两条证据；投资方文章支持领投关系，不能据此单独填金额。重复添加官网 URL 仅提示已有文档；同文档若提及累计融资，不自动生成第二轮。

## 9. 更新与失败机制

首版“更新”指人工复核：打开原始链接、确认仍可读、补充/修订摘录或标记访问失败，保存核验记录。公司原始信息和旧证据版本不被网络状态覆盖。

| 情形 | 预期行为 |
| --- | --- |
| URL 不合法或必填缺失 | 保存前拒绝，表单内容保留；不发远程请求 |
| 断网、登录墙、付费墙、404/403、正文无法核对 | 人工记录“访问失败/待核验”及时间；保留上次有效依据，不推导融资撤回 |
| 页面修改 | 先区分补充说明、正文更正和交易本身变化；保存版本与修改理由，不能自动算新一轮 |
| 来源撤稿/明确更正 | 只有看到明确证据才标更正/撤回；保留旧版并提示依据，不硬删历史 |
| 多条录入中一条失败 | 每条事务独立；成功部分保留，失败可重试；相同幂等键不重复建事件 |
| 进程重启/数据库写入失败 | 已提交事务持久化，未成功内容保持草稿；错误可见，不显示“已保存” |

自动刷新留到后续单独批准的来源适配器：需要先核验访问权限、字段契约和增量游标。成功获取且通过校验才推进游标；分页中断保留上次完整检查点并幂等重放；401/403/429 停止或按来源指引退避，5xx/网络失败保留旧数据。来源的数据库更新时间只用于增量发现，不改变事件发生日。未实现前界面不得展示自动更新成功状态。

## 10. 可执行交付与验收

建议实现顺序：模型/迁移与事务 → 手动 API/重复候选 → 融资列表与详情/录入 → 关联已有公司 → 版本/核验记录 → 隔离测试 → 用户三案例复核。此顺序是后续开发建议，本轮没有执行。

| 编号 | 验收操作 | 通过条件 |
| --- | --- | --- |
| F01 | 在隔离数据库录入 BoldVoice 公司新闻稿，选择研究报告中的公司身份 | 记录公告日；发生日可空；首次发现为实际录入时间；标公司发布，不称独立验证；不自动确认 App |
| F02 | 录入 Agave 官网公告，再追加 Accel 公告 | 一轮事件、两条证据；本轮金额与累计融资分开；领投字段和金额字段各指向实际支持来源 |
| F03 | 重复提交 F01；重复粘贴同一来源带追踪参数的 URL | 幂等请求不新增事件；URL 复用提示清楚；不误删业务查询参数，不限制一份文档只能对应一轮 |

| F05 | 合成测试样本：同名不同官网、同公司不同轮次、A 轮追加、金额/日期冲突 | 不自动跨公司合并；不同轮次可共存；追加关系保留；冲突不覆盖旧证据。合成样本明确标测试数据 |
| F06 | 合成金额：本轮/累计/估值、数千万、下界、币种未明、混合债务 | 原始口径可还原；未知为 null，不能变 0 或精确金额；不相加、不擅自换汇 |
| F07 | 修改金额/归属公司，A→B→A；同字段重新保存；再次核验无变化 | 三个真实变更版本可追溯；相同字段不重复出版本；核验与事件变更分开 |
| F08 | 标记证据访问失败、撤稿待核验，模拟数据库写入失败 | 已有记录和历史不丢失；无证据不判断融资撤回；失败表单草稿可恢复 |
| F09 | 关闭服务再重启，读取事件、来源关系、笔记；解除公司/App 关联 | 已提交数据保留；既有 App、榜单、增长笔记不改写；解除 App 关联不删除融资 |
| F10 | 创建只有融资的公司，再查看增长统计和选择器 | 增长统计不虚增；融资可独立研究；通用公司选择器可找到新公司；不存在虚构岗位 |
| F11 | 列表分别按公告日与发现日筛选旧公告；未知日期展示 | 两种时间语义清楚；旧公告今天收录不显示为今天完成；空日期不回填 |
| F12 | 构建、规则/API、隔离浏览器测试及人工真实案例复核 | 明确实际通过项和未完成项；不把单纯构建成功当验收，不在真实数据库播种测试线索 |

首次实体验收至少包含两笔真实轮次、其中一笔多来源，以及一条证据不足的线索。测试用数据库与真实个人数据隔离；后续是否由用户把这些记录纳入自己的研究库另行安排。融资视图和增长视图并列展示只能启发研究，不生成 PMF 或投资回报判断。
