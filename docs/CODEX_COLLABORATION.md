# Codex 分工协作与换机接续

更新：2026-11-02（北京时间）。本项目用四个长期对话分工，仓库文档保存共同上下文。换电脑后，以当前代码、架构决策和进度记录恢复工作，不依赖旧聊天记录。

## 从哪里开始

按顺序阅读根目录 `AGENTS.md`、[项目范围](PROJECT.md)、[架构决策](ARCHITECTURE.md)、[当前进度](STATUS.md)，再读任务对应的设计、研究和验收记录。

| 文件 | 保存内容 | 主维护方 |
| --- | --- | --- |
| `AGENTS.md` | 工作边界、文件归属、数据和验收规则 | 总控 |
| `docs/PROJECT.md` | 定位、已确定范围、优先级、角色登记 | 总控 |
| `docs/ARCHITECTURE.md` | 已接受的架构决策及原因 | 总控 |
| `docs/STATUS.md` | 完成证据、进行中任务、阻塞和接续点 | 总控 |
| `docs/design/` | 模型、API契约、交互和待执行方案 | 专项主维护，总控协调 |
| `docs/research/` | 真实样本、来源、反例、机会假设 | 产品研究 |
| `docs/qa/` | 联合验收、环境、通过项和限制 | 总控 |

聊天中的重要决定、未完成项和验证结果必须回写这些文件。建议、开发中、待验收、已验收分别记录；写了设计不等于批准开发，构建通过不等于完成验收。

根目录 `AGENTS.md` 是 Codex 的项目指令入口；全局或更深目录的指令也可能影响行为。新会话应确认实际读取了哪些规则。[官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 四个长期对话

| 建议名称 | 负责什么 | 主要改动范围 |
| --- | --- | --- |
| Deltabase · 项目总控与架构 | 拆任务、排优先级、公共模型决策、协调依赖、联合验收、统一提交同步 | 三份项目主文档、协作规则、集成记录 |
| Deltabase · 前端和交互设计 | 页面、组件、交互、可访问性、浏览器验证 | `src/`、相关E2E；融资具体归属见 `AGENTS.md` |
| Deltabase · 数据采集与后端 | 采集、数据库、迁移、实体匹配、去重、变化、API | `server/`、共享类型与规则/API测试；先落地接口契约 |
| Deltabase · 产品研究与机会验证 | 真实案例、原始证据、反证、用户任务、实验 | `docs/research/`；不把假设写成事实 |

旧对话ID保存在 `PROJECT.md`，只用于当前环境定位；它们不是可移植配置。Git克隆不会创建或固定这些对话，也不会导入聊天历史、运行进程、账号授权或个人技能。新电脑若能访问原对话，可继续使用，但先核对关联的工作目录；无法访问时，在新克隆目录重建同样的角色并登记新ID。无需复制本机绝对路径或依赖个人插件才能理解项目。

只有一项小改动时，由一个对话完成即可。需要专项协作时，总控指定唯一主改方和交付物；工具不支持跨对话发送时，用下方任务卡和仓库文件交接。不要假设其他对话会自动收到上下文。

## 一次迭代怎样执行

1. 总控核对 `git status`、分支、当前进度和用户最新目标，确定本次范围与验收。已有授权内的工作继续推进；尚未批准的建议保持建议状态。
2. 将任务分给对应角色，明确可改文件、共享文件主改方、依赖、端口和测试数据目录。涉及模型/API时，后端先写契约，再交前端读取；变更必须解释兼容方式。
3. 专项完成各自实现与验证，报告改动、结果、限制、未完成项。共用checkout时保留其他对话改动，不擅自切换分支、重置、清理或提交全部目录；不重启他人服务。
4. 总控集成并执行适用验证：规则/API测试、构建、隔离E2E和真实样本核对。3100端口E2E同一时间只给一个执行者，移交后再复验。
5. 总控更新决策与状态，只提交明确归属的文件；检查个人数据和凭据未入库，再同步GitHub，记录分支/提交和远程验证结果。

同一checkout内分工使用同一个迭代分支；需要隔离开发时先协调worktree与文件归属。新开发分支统一使用 `codex/` 前缀。不要在其他对话写文件时自行更换它们的分支。

可复制的任务卡：

```text
目标与当前授权：
负责人 / 唯一主改文件：
基线分支与提交：
输入文档与前置依赖：
接口或迁移兼容要求：
验收场景 / 命令 / 隔离数据目录 / 端口：
交付文档与状态回写位置：
未完成项、阻塞及下一步：
```

任务中断或换机前，把具体任务卡写进 `docs/STATUS.md` 的接续记录；较长方案单独放 `docs/design/` 并链接。至少留下当前分支/提交、已完成、未完成、失败原因、测试证据和下一步。不要只留下“继续之前的工作”。

## 新电脑首次启动

安装Git和Node.js 24，并确保新电脑能访问私有仓库。Codex登录、GitHub连接器授权和命令行Git认证分别检查，不能由其中一个已登录推定另一个也可用。下面命令适用于macOS/Linux的bash或zsh；当前npm脚本/E2E使用POSIX环境变量语法，Windows建议在WSL中执行，原生PowerShell路径未验收。

```bash
git clone https://github.com/Pyroblast/deltabase.git
cd deltabase
git status --short --branch
# 已安装nvm时执行；其他安装方式请确保node -v为v24.x
nvm install
nvm use
npm ci
npm test
npm run build
npx playwright install chromium
npm run test:e2e
AUTO_SYNC=0 npm start
```

先用 `AUTO_SYNC=0` 启动以核对页面和本地环境，打开 <http://127.0.0.1:3000>；首次页面没有历史数据是正常的。需要采集时手动刷新，或停止服务后用 `npm start` 启用默认启动检查。运行需要网络、可写数据目录和可用端口；Playwright在Linux上还可能需要安装系统依赖。按实际报错解决，不把旧电脑测试通过当作新环境已验收。

不要复制旧电脑的 `node_modules/` 或 `dist/`。本项目含原生SQLite依赖，须在目标环境按锁文件安装与构建。当前应用不需要融资供应商或OpenAI API密钥；后续接入另按对应方案配置，不能把密钥写入仓库。

然后在Codex打开这个克隆目录，新建或使用总控对话，发送：

```text
你接任 Deltabase 项目总控与架构。先读取 AGENTS.md、docs/PROJECT.md、
docs/ARCHITECTURE.md、docs/STATUS.md、docs/CODEX_COLLABORATION.md，
核对当前工作目录、分支、提交及未提交改动。
根据仓库区分已交付功能、未完成工作和待批准建议，指出下一步。
沿用总控、前端、后端、产品研究四角色分工；已有对话可用就复用，
需要新建时按我的指令创建，不把旧对话ID当作新电脑的有效配置。
保留个人数据，使用隔离测试库；专项按文件归属执行，总控统一验收和同步GitHub。
我本次要继续的目标是：〈填写具体目标〉。
```

给专项对话的启动语：`你负责 Deltabase 的〈角色〉。先读项目协作与状态文档，再执行总控提供的任务卡；仅修改分配文件，报告验证和未完成项，交总控集成。`

## 两台电脑之间交接

离开旧电脑前：保存文件，将工作进度写入仓库；总控检查后提交并推送当前分支。未验收工作可保存为明确标记的WIP分支，不能标记已交付。GitHub不会带走未提交文件。

另一台电脑已有克隆时，先检查是否有本地改动，再获取远程状态；工作区干净且当前分支没有分叉时才快进更新：

```bash
git status --short --branch
git fetch origin
# 核对并切到交接记录指定的分支后执行；有本地改动/分叉时先协调
git pull --ff-only
npm ci
```

常规新迭代从同步后的基线建立 `codex/<任务名>`；接续WIP则使用交接记录指定的已有分支。两台电脑同时开发要分别使用不同分支并由总控合并，不用强推覆盖对方工作。

| 内容 | GitHub是否带走 | 接续方式 |
| --- | --- | --- |
| 源码、锁文件、迁移、协作/设计/研究/验收文档 | 已提交并推送后带走 | 克隆/拉取，重新安装构建 |
| SQLite、收藏、笔记、手动录入和采集历史 | 不带走 | 需要时单独安全迁移在线备份 |
| Codex对话、固定状态、本地路径、进程 | 不随Git仓库带走 | 新环境核对或重建 |
| Git认证、供应商凭据、个人插件/技能 | 不带走 | 按需在新电脑配置；无相应工具时用文档交接 |

个人数据若需迁移：旧电脑在项目根目录运行 `npm run backup`（使用自定义 `DATA_DIR` 时传入同一目录），单独安全传输生成的备份；新电脑先停止服务，再按 [README的恢复流程](../README.md#更新和存储)还原。保留目标旧库及WAL/SHM以便恢复，不混用旧WAL。Git不合并两台电脑的SQLite记录；选择一个数据主副本，避免分别修改后期待自动合并。
