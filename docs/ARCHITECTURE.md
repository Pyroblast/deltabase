# Deltabase 核心架构决策

更新：2026-11-01（北京时间）。这些是已确定原则，新增决策记录日期、原因和影响。

## ADR-001 本地数据库与动态工作台

React 查询 Fastify API，Node 负责采集，SQLite/Drizzle 保存业务数据与历史。不是每天生成静态网页。默认监听 127.0.0.1；服务不运行时不采集。启动检查与手动更新不等于定时任务。

## ADR-002 信源独立，身份可关联

App 使用 Apple ID，商店信息与排名按市场分开，收藏与笔记跨市场共享。增长模块保留公司、岗位/活动、版本与观察记录，并由用户确认公司与 App 的关联。不能仅靠同名自动合并，也不能把招聘发布机构等同于推广产品主体。

融资沿用公司/产品关联原则；不要求没有 App 的公司拥有虚构 App 身份。跨来源公共实体层的进一步抽象需以真实案例证明必要性。

## ADR-003 证据与时间

原始证据、来源 URL、采集时间、来源提供的时间分别保存。融资区分发生、公告、发现时间。首次采集是基线；首次发现不等于新发布。相邻采样不假定间隔一天；曲线不插补未知数据。

## ADR-004 变化与失败

重复快照/内容去重；空榜不推导退出，未出现在列表不推导关闭；采集失败保留最近有效数据并显示失败。确定性规则负责比较与数值处理。原始事实、公司自述、第三方估算、研究推断必须可区分。

## ADR-005 信源二 MVP

YC Jobs 公开 Marketing 页面和详情为自动采集入口，只声明公开样本覆盖。SideShift/Wellfound 保存人工线索，不将自己的公司管理 API 当作全平台情报接口。规则分类需展示原文依据；薪资、单条内容报酬、月度合作费、总预算各保留口径。

## ADR-006 交互

石墨白中性主题、紧凑列表、证据侧栏；保留筛选上下文与笔记草稿；完整档案支持深度研究。状态文案区别基线、未观察到、持平、过期和失败。

## ADR-007 版本与数据边界

GitHub 私有仓库保存代码、测试、迁移和项目文档。真实 SQLite、备份和个人研究操作数据留在本地。备份使用 SQLite 在线接口；恢复前停服务，避免混用旧 WAL。

## ADR-008 融资公告手动MVP（2026-11-01）

用户已批准实施。首版复用 `growth_companies` 的身份与现有App关联，纯融资公司使用 `company:<uuid>`，无需虚构岗位。增长列表与统计限定实际有增长线索的公司；融资可查看所有公司。新增表与迁移保持旧App/增长数据兼容。

融资事件与来源文档分开，一轮可有多来源，一文可支持多轮；字段解释和所选依据属于事件版本，不因另一个事件编辑共享文档而悄悄改变。金额保留原文、范围和本轮/累计/估值口径，不做汇总和币种推断。发生、公告、发现时间独立，未知不补今天。

写入采用事务、幂等键和预期版本检查：同请求重试返回原结果，同键不同内容与过期编辑返回冲突。相同文档URL复用，疑似同轮提示由人决定追加来源或另建并记录理由；不按同名自动合并。保留A→B→A历史，单纯再次核验记录观察而不制造新版本。归档重复记录保留来源与历史。

原始链接只允许无凭据的HTTP(S)，服务器不请求这些输入URL。前端草稿在失败时保留，冲突不静默覆盖。当前交付由前端/后端/研究三个长期对话分工，总控统一验收与发布。
